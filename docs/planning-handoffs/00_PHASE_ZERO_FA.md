# تحویل مرحلهٔ صفر

شاخه: `codex/planning-phase-zero`؛ commit مبنا: `d3695a6b35940d4c1c845fa738d5b36c80734532`. خروجی: commit همین گزارش و تغییرات مرحلهٔ صفر روی همین شاخه؛ main تغییر نکرده و انتشار انجام نشده است.

## انجام‌شده

۱. قرارداد مدل، writerها، timezone، saved/queued/failed، روابط، waiting، WIP، مرور و مهاجرت در `docs/PLANNING_EXECUTION_CONTRACT_FA.md` ثبت شد. قسمت‌های مربوط به بسته‌های آینده مشخصات‌اند، نه قابلیت اجراشده.

۲. datetime صریح v2 ساعت‌های ۰۰:۰۰ و ۲۳:۵۹ را حفظ می‌کند. inference روز بدون ساعت فقط برای reader قدیمیِ غیر exact است. دادهٔ legacy exact در ساعت مرزی datetime می‌ماند.

۳. direct work_date و period writerها جایگزینی کامل می‌سازند. پاک‌کردن، period زیرین را زنده نمی‌کند. دو برنامهٔ هم‌زمان، دورهٔ ناقص و تاریخ نامعتبر رد می‌شوند. persistTask خطای validation را failed می‌کند و پیش از تغییر کش متوقف می‌شود. AI applyMeta از workDatePatch استفاده می‌کند.

۴. schedule_timezone برای زمان دقیق اضافه شد. API روز را با zone معتبر ذخیره‌شده یا زمینهٔ صریح کاربر محاسبه می‌کند؛ datetime با zone نامشخص روز حدسی نمی‌گیرد. بازهٔ query تاریخ نیز همین روز تقویمی را می‌خواند. مسیرهای server create/patch برای زمان واقعی zone اختیاری را عبور می‌دهند. دادهٔ قدیمی بدون zone در فیلتر تاریخ محلی API unknown است؛ instant آن حذف نمی‌شود. schema عمومی در بستهٔ ۶ باید تکمیل شود.

۵. اجرای خودکار migrateTaskSchedules از subscription ورود حذف شد. helper قدیمی هنوز موجود است، ولی ابزار مهاجرت ایمن نهایی نیست و به login وصل نشود. اجرا روی حساب واقعی انجام نشد. مرحلهٔ بعد باید dry-run، انتخاب تعارض و transaction/CAS را مطابق قرارداد بسازد.

۶. نمودار مسیر در `docs/PLANNING_PHASES.svg` و نسخهٔ Mermaid در قرارداد اضافه شد. طراحی برنامه، CSS، تم، layout، manifest، lockfile و Vercel تغییر نکردند.

## تست و شواهد

- سیدنی: ۷ فایل مرتبط، ۶۸ تست موفق، شامل ۱۰ تست قرارداد مرحلهٔ صفر و آزمون‌های schedule/adapter/migration/recurrence/taskService/taskDate.
- منطقهٔ زمانی منفی: آزمون‌های قرارداد در لس‌آنجلس بررسی شدند؛ نتیجهٔ اجرای نهایی در فایل evidence آمده است.
- typecheck و build frontend اجرا شدند؛ نتیجهٔ نهایی build در `evidence/phase-zero-build.txt` است. هشدار اندازهٔ chunkهای بزرگ مربوط به خروجی فعلی باقی است.
- سه ماژول تغییرکردهٔ API با esbuild برای Node bundle شدند؛ این کار تأیید استقرار واقعی یا جایگزین تست endpoint نیست.
- تست‌های کامل API به علت خطای بارگذاری مسیر در runner نصب‌شده اجرا نشدند: Cannot find module /api/... و /@fs/... . فایل‌ها و تنظیم آزمایشی موقت پاک شدند. این خطا را رفع باگ endpoint یا تست موفق گزارش نکن.
- محیط از node_modules موجود استفاده کرد؛ Vitest نصب‌شده ۴.۱.۱۱ و manifest ۳.۲.۴ است. نصب تازه مطابق lockfile و تست endpoint/استقرار باقی است.
- تست مستقل تصویری UI اجرا نشد؛ مرحلهٔ صفر تغییر markup/style نداشت. نمودار SVG از نظر XML معتبر است.
