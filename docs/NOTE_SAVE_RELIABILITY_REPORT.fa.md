# اصلاح قابلیت اعتماد ساخت نوت

مبنا: main در commit `18adba6870e5aba8c02103e90a9d7ed410cd1013`.

## مشکل و اصلاح

صفحهٔ نوت جدید نتیجهٔ boolean را به‌اشتباه تفسیر می‌کرد: صف آفلاین موفق را همگام‌شده و شکست کامل را ذخیره‌شده در صف نشان می‌داد و از صفحه خارج می‌شد.

- قرارداد `persistNote` اکنون سه نتیجهٔ synced/queued/failed دارد. `upsertNote` برای مصرف‌کنندگان فعلی همان قرارداد boolean پذیرش را حفظ می‌کند.
- شکست ذخیره، فرم و متن را نگه می‌دارد و پیام خطا می‌دهد؛ فقط پذیرش ابری یا صف پایدار موجب خروج می‌شود.
- تلاش مجدد همان شناسه را استفاده می‌کند؛ ارسال هم‌زمان مسدود و فرم هنگام ذخیره غیرفعال است.
- تغییر حساب فرم جداگانه می‌سازد؛ نتیجهٔ دیرهنگام فرم قبلی پیام موفقیت یا تغییر مسیر در حساب جدید ایجاد نمی‌کند.

## شواهد و محدودیت

۱۶ آزمون مرتبط موفق: نتیجهٔ سه‌حالتی، rollback کش و حفظ ویرایش هم‌زمان، شکست و تلاش مجدد با شناسهٔ ثابت، حفظ متن، تفکیک صف از همگام‌سازی و پاسخ دیرهنگام حساب قبلی.

این اصلاح تضمین حفظ متن در شکست ذخیره در همان صفحه است؛ ماندگاری نوت جدید پس از Back/reload هنوز نیازمند اتصال به پیش‌نویس مشترک است. حساب واقعی و همگام‌سازی چند دستگاه طبق خواستهٔ کاربر آزمایش نشده‌اند.

## صف بعدی

- پیش‌نویس پایدار و Undo مشترک برای نوت جدید و سایر ادیتورهای باقی‌مانده.
- تطبیق صف‌های مطالعه و قرارداد ذخیرهٔ هدف/آزمون با نتیجهٔ واقعی.
- سپس تنظیمات، مسیر AI و اتصال‌های بخش‌های عمومی طبق فایل تحویل موجود.
