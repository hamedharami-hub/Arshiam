# تحویل بازبینی نهایی Sol — بسته‌های ۰ تا ۶

شاخه: `codex/planning-phase-zero`
این گزارش، گزارش‌های بسته‌های ۰۰ تا ۰۶ را با کد نهایی تطبیق می‌دهد. هیچ push، merge، انتشار، نوشتن روی حساب واقعی یا مهاجرت واقعی انجام نشد.

## نتیجهٔ بازبینی

- باگ مستقل `useTodayPlanning` که به‌علت برابرشدن `undefined === undefined` snapshot تهی را می‌خواند اصلاح شد؛ آزمون حالت بدون uid نیز اضافه شد.
- ایراد باقیماندهٔ نشان هدف در Plan اصلاح شد: فقط تسک باز و زمان‌بندی‌شده در سال جاری هدف را «در برنامه» نشان می‌دهد. تسک سال بعد، `done`، `completed` و `wont_do` دیگر نشان را فعال نمی‌کنند.
- در برابر باگ‌های گزارش اولیه، موارد ۱ تا ۹، ۱۱ تا ۱۴ و ۱۶ در کد/آزمون پوشش دارند؛ حدود تأییدشان در جدول زیر آمده است. مورد ۱۵ با اصلاح این بازبینی تکمیل شد.

## آزمون‌های نهایی

- `npm test -- --run` در `frontend/`، پس از اصلاح `useTodayPlanning` و پیش از اصلاح نهایی نشان هدف: ۲۳۳ فایل و ۱٬۹۸۵ تست موفق، بدون شکست.
- `npm test -- --run src/lib/taskSchedule.test.ts` پس از اصلاح نشان هدف: ۱ فایل و ۱۷ تست موفق.
- `npm run typecheck` پس از اصلاح نشان هدف: موفق.
- `npm run build` پس از آخرین اصلاح نشان هدف — موفق؛ Vite و PWA خروجی تولید کردند. هشدارهای موجود دربارهٔ chunkهای بزرگ و importهای استاتیک/پویا دیده شدند.
- بستهٔ ۰۶: آزمون‌های هدفمند AI هفت فایل/۴۲ تست و API دو فایل/۳۸ تست موفق؛ گزارش بسته جزئیات فرمان‌ها را دارد.
- دو سند OpenAPI به JSON معتبر parse شدند؛ `git diff --check` موفق بود.

## محدودیت‌های قابل توجه

- `frontend/node_modules` یک symlink محلیِ خارج از Git است؛ نسخهٔ Vitest نصب‌شده 4.1.11 است، درحالی‌که manifest نسخهٔ 3.2.4 را می‌خواهد. در مخزن lockfile استاندارد npm/yarn/pnpm/bun پیدا نشد؛ بنابراین نصب تمیز مطابق lockfile قابل تأیید نبود.
- package ریشه اسکریپت build مستقل API ندارد. آزمون‌های API اجرا شده‌اند، اما build واقعی Vercel یا deploy آزمایشی انجام نشد.
- تست‌ها و تصاویر مرورگر از دادهٔ ساختگی بودند. migration، مجوزهای Firestore، ذخیرهٔ واقعی، همگام‌سازی چند دستگاه و تمام سناریوهای پذیرش E2E تأیید زنده نشدند.
- overflow فعلی Plan در موبایل نسبت به baseline انگلیسی تازه ایجاد نشده، اما هنوز باقی است و برای اصلاحش باید یک تغییر layout کوچک و هدفمند جداگانه بررسی شود.
