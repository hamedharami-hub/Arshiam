# اتصال ChatGPT به ارشیام با MCP

## وضعیت

پیاده‌سازی محلی روی نسخهٔ `750e6ee` انجام شده است. سرور MCP، OAuth و ابزارها در آزمون‌های کنترل‌شده بررسی شدند؛ هنوز اتصال واقعی از حساب ChatGPT یا انتشار این تغییرات انجام نشده است.

## آدرس و ورود

- آدرس پیشنهادی اتصال: `https://arshiam.vercel.app/api/mcp`
- روش احراز هویت: OAuth Authorization Code با PKCE/S256 و کلاینت عمومی ثبت‌شده با DCR.
- resource باید دقیقاً آدرس `/api/mcp` باشد؛ توکن برای REST یا سرویس دیگری معتبر نیست.
- کاربر در صفحهٔ `/app/connect/chatgpt` با حساب فعلی Firebase اجازه می‌دهد. مجوزهای درخواستی روی صفحه نمایش داده می‌شوند.
- اعتبار grant سی روز، اعتبار access token حداکثر پانزده دقیقه است. refresh token در هر استفاده تعویض می‌شود؛ کد ورود یک‌بارمصرف و دو دقیقه معتبر است.
- لغو grant از تنظیمات اتصال عامل‌ها، دسترسی access و refresh را قطع می‌کند.
- هیچ API مدل هوش مصنوعی برای این قابلیت فراخوانی نمی‌شود.

SDK سرور به `@modelcontextprotocol/sdk@1.32.1` قفل شده و نسخهٔ پایهٔ پروتکل آن `2025-11-25` است. ادعای پشتیبانی نسخهٔ `2026-07-28` نداریم. انتقال Streamable HTTP با پاسخ JSON، بدون session حافظه‌ای بین درخواست‌ها، استفاده می‌شود.

## ابزارها و مجوزها

| ابزار | مجوز |
|---|---|
| `get_profile`، `get_context` | اتصال احراز‌شده |
| `list_tasks`، `get_task`، `get_schedule` | `tasks:read` |
| `list_folders` | `folders:read` |
| `search_notes`، `get_note` | `notes:read` |
| `create_task` | `tasks:create` |
| `update_task`، `complete_task` | `tasks:update` |
| `create_note` | `notes:create` |
| `update_note` | `notes:update` |

تغییر داده به مجوز سمت سرور وابسته است. ابزار بدون مجوز، خطای scope و challenge اتصال مجدد می‌دهد. انتخاب اولیهٔ discovery فقط `tasks:read` است؛ افزایش دسترسی باید با تأیید OAuth انجام شود.

یادداشت عمومی `kind` خالی یا `note` و `task_id` خالی دارد. Diary، یادداشت اختصاصی تسک و محتوای سلامت وارد ابزارهای نوت نمی‌شوند. شناسهٔ حساب از توکن خوانده می‌شود؛ ورودی ابزار انتخابگر حساب ندارد.

خواندن مجموعه‌ها در صفحه‌های حداکثر صد ردیف انجام می‌شود؛ cursor به آخرین ردیف اسکن‌شده اشاره دارد. حتی صفحهٔ فیلترشدهٔ خالی ممکن است `next_cursor` داشته باشد. متن نوت در قطعه‌های دوازده‌هزارکاراکتری خوانده می‌شود. ویرایش نوت بزرگ‌تر در خود برنامه انجام می‌شود تا قطعهٔ اول جای کل سند نوشته نشود.

## قواعد نوشتن

- `operation_id` برای هر عملیات مستقل تازه و در retry همان عملیات ثابت است.
- ساخت از handler مشترک Agent API و رسید تراکنشی موجود عبور می‌کند.
- ویرایش با `expected_revision` و ثبت receipt در همان تراکنش انجام می‌شود.
- تکرار receipt همان نتیجه را برمی‌گرداند؛ ID تکراری با ورودی متفاوت خطای تعارض می‌دهد.
- receiptها برای بازپخش حداقل در پنجرهٔ ۲۴ساعته به کار می‌روند؛ پس از این پنجره تضمین عدم تکرار قصد قدیمی وجود ندارد.
- عملیات تکمیل و ویرایش روی تسک تکرارشونده یا آموزشی، و تکمیل تسک دارای outcome، به اقدام در خود برنامه ارجاع می‌دهد؛ این نسخه گردش کار ویژه را شبیه‌سازی نمی‌کند.
- API قدیمی memories برای سازگاری مجوزهای قبلی باقی است؛ اتصال OAuth جدید فقط مسیر notes عمومی را استفاده می‌کند.
- `get_schedule` بازهٔ تاریخ محلی و timezone صریح می‌گیرد و تعهد بازه‌ای را با کار امروز یکی نمی‌کند. endpoint قدیمی روز/هفته/ماه هم timezone، مرز UTC برای تاریخ محلی و week_starts_on معتبر را می‌پذیرد. نمای ماه این endpoint میلادی است؛ برای بازهٔ شمسی، ابتدا تاریخ‌های دقیق بازه تعیین شوند.

## آماده‌سازی استقرار

1. انتشار endpointهای جدید در همان پروژهٔ Vercel، پس از درخواست صاحب پروژه.
2. بررسی تنظیم موجود Firebase Admin؛ بدون آن سرور دادهٔ حساب را نمی‌خواند و پاسخ 503 می‌دهد.
3. در صورت تفاوت دامنه، `MCP_PUBLIC_ORIGIN` باید origin HTTPS بدون مسیر باشد. دامنهٔ resource و callback metadata باید با نسخهٔ منتشرشده هماهنگ باشند.
4. rewriteهای `.well-known/oauth-protected-resource` و `.well-known/oauth-authorization-server` باید JSON برگردانند، نه index.html.
5. OAuth recordها و rate-limitها در مجموعه‌های سطح بالای `mcp_oauth_*` و `mcp_rate_limits` هستند. قوانین فعلی دسترسی wildcard به مجموعهٔ سطح بالا نمی‌دهند؛ دسترسی فقط Admin است.
6. retention/پاک‌سازی مجموعه‌های کد و توکن باید در محیط استقرار تنظیم شود. انقضا در کد اعمال می‌شود، اما حذف فیزیکی رکوردها خودکار فعال نشده است؛ TTL یا job پاک‌سازی نیاز به تنظیم مستقل دارد.
7. محدودیت نرخ در Firestore مشترک میان instanceهاست؛ هزینهٔ عملیاتی خواندن/نوشتن آن باید در استفادهٔ واقعی پایش شود.
8. صفحهٔ اتصال سفارشی ChatGPT را باز کنید، URL و OAuth را انتخاب کنید و چرخهٔ ورود واقعی را آزمایش کنید. دسترسی این صفحه تابع حساب و سیاست workspace است؛ در این محیط تأیید نشده است.

## آزمون‌های اجراشده

- OAuth: callback معتبر، S256، اتصال account/resource/client، یک‌بارمصرف‌بودن code، چرخش refresh، لغو grant، رد PAT و رد scope خاطرات.
- MCP: کشف ابزار، خطای scope، جداسازی نوت خصوصی/حساب دیگر، retry ساخت و ویرایش، revision conflict، تکمیل ساده و جلوگیری از تغییر تسک تکراری.
- انتقال واقعی localhost HTTP با SDK client: initialize، tools/list، tools/call و رد origin نامعتبر/توکن لغوشده.
- رابط اجازه: مجوز نامعتبر غیرفعال است؛ بدون کلیک صریح درخواست اجازه ارسال نمی‌شود؛ خطای OAuth نمایش داده می‌شود.
- تست‌های قبلی Agent API و schema موفق بودند؛ TypeScript بخش frontend و typecheck جداگانهٔ endpointهای جدید موفق شدند. ساخت frontend/PWA هم موفق شد.

اتصال واقعی ChatGPT، تعامل دو حساب Firebase روی سرور منتشرشده، TTL واقعی، بازپخش پس از cold start روی Vercel و بررسی کارایی تولید هنوز انجام نشده‌اند. آزمون localhost ادعای موفقیت این موارد نیست.
