## خلاصه

بخش «مخزن ابزارک‌های HTML» بررسی و اصلاح شد. افزودن مستقیم کد، پاک‌سازی حصار کد خروجی هوش مصنوعی، هشدارهای سازگاری و نمایش خطاهای اجرای پیش‌نمایش اضافه شده‌اند. باگ‌های ورود غیرهم‌زمان فایل، چرخه عمر حساب و پیش‌نمایش، و چند حالت مرزی نیز اصلاح شدند.

تغییرات در شاخه جدا تحویل می‌شوند؛ در این کار شاخه اصلی merge نشده و نسخه زنده منتشر نشده است. داده‌های واقعی Firebase در آزمون‌ها خوانده یا تغییر داده نشدند.

| مورد | مشکل قبلی | اصلاح |

چهار مورد اول مربوط به ورود فایل که به صورت شکست واقعی تست قبل از اصلاح ثبت شدند: بازنویسی تغییرات هم‌زمان، پذیرش ورودی خالی، ذخیره پس از unmount و ریست‌نشدن ورودی فایل. سایر موارد با بازبینی کد و تست‌های بازگشت پوشش داده شدند.

## امکانات اضافه‌شده

- **چسباندن HTML:** پنجره جدا برای واردکردن نام و یک فایل کامل یا قطعه HTML؛ مناسب کدی که از هوش مصنوعی گرفته شده است.
- **حذف حصار کد:** حصار Markdown فقط وقتی کل ورودی را پوشانده باشد در ورود فایل/چسباندن باز می‌شود. در ویرایشگر نیز دکمه صریح «حذف حصار کد» نمایش داده می‌شود؛ توضیح بیرون از حصار و HTML اصلی بی‌اجازه بازنویسی نمی‌شوند.
- **اعتبارسنجی حجم:** سقف واقعی **۱۲۰٬۰۰۰ بایت UTF-8** است؛ نمایش KB بر مبنای ۱۰۰۰ بایت است و حروف فارسی نیز با حجم واقعی سنجیده می‌شوند.
- **هشدار سازگاری:** تشخیص سبکِ برخی منابع بیرونی، درخواست شبکه و APIهای ذخیره‌سازی مرورگر؛ هشدار جلوی افزودن کد غیرخالیِ در محدوده حجم را نمی‌گیرد.
- **گزارش خطا:** نمایش خطاهای JavaScript، Promise و نقض CSP در پیش‌نمایش؛ حداکثر ۵ پیام و ۱۰۰۰ کاراکتر برای هر پیام. پیام‌ها متن غیرقابل‌اجرا هستند و در اجرای جدید پاک می‌شوند.
- **بازخورد ورود فایل:** وضعیت خواندن فایل و پیام موفقیتِ ذخیره محلی، بدون ادعای تأیید ذخیره ابری.
- **حفظ رفتار فعلی:** ظاهر فارسی/انگلیسی، پیش‌نویس قابل‌بازیابی و هشدار پیش‌نمایش قدیمی حفظ شده‌اند. تایپ، ذخیره، ورود فایل یا چسباندن کد باعث اجرای خودکار کد جدید نمی‌شوند.

فرمان‌های قابل تکرار از پوشه `frontend`:

```bash
npm test -- src/pages/MiniAppsView.test.tsx src/lib/miniAppsHtml.test.ts src/lib/miniAppsSandbox.test.ts
npx eslint src/pages/MiniAppsView.tsx src/pages/MiniAppsView.test.tsx src/lib/miniAppsHtml.ts src/lib/miniAppsHtml.test.ts src/lib/miniAppsSandbox.ts src/lib/miniAppsSandbox.test.ts --max-warnings 0
npm run build
```

برای نصب اولیه، `npm ci` در ریشه مخزن و سپس در پوشه `frontend` لازم است؛ بررسی TypeScript به وابستگی API ریشه نیز نیاز دارد.

**دامنه آزمون:** تست‌های مرتبط با HTML و بررسی TypeScript/build کل فرانت‌اند اجرا شدند؛ کل مجموعه تست همه صفحات برنامه و همگام‌سازی با Firebase واقعی اجرا نشده است. هشدارهای build درباره ترکیب import ایستا/پویا در ماژول‌های دیگر برنامه همچنان وجود دارند و مانع build نیستند.

## ساختار مرتبط

- `frontend/src/pages/MiniAppsView.tsx`: کتابخانه، ویرایشگر، ورود فایل/کد، پیش‌نمایش و چرخه عمر حساب.
- `frontend/src/lib/miniAppsStore.ts`: محدودیت‌ها و ذخیره‌سازی حساب‌محور؛ فایل موجود و بدون تغییر در این اصلاح.
- `frontend/src/lib/miniAppsSandbox.ts`: CSP، اجرای iframe و رابط محدود برنامه، به‌علاوه گزارش خطا.
- `frontend/src/lib/miniAppsHtml.ts`: بازکردن حصار و هشدارهای سبک، بدون اجرا یا تجزیه DOM کد کاربر در صفحه اصلی.

## محدودیت‌های باقی‌مانده

1. هشدارهای سازگاری مبتنی بر الگو هستند؛ اعتبارسنجی کامل نحو HTML/JavaScript یا تضمین بی‌باگ‌بودن کد نیستند و ممکن است هشدار کاذب یا موارد تشخیص‌داده‌نشده داشته باشند.
2. گزارش خطا برای خطاهای منتشرشده توسط مرورگر است؛ خطاهای منطقی یا خطاهایی که خود ابزارک catch کند الزاماً دیده نمی‌شوند. شماره خط مربوط به سند تولیدشده پیش‌نمایش است، نه دقیقاً فایل اصلی.
3. iframe بدون `allow-same-origin` و CSP حفظ شده‌اند. درخواست‌های معمول شبکه مسدودند، اما رفتار self-navigation، `location` و meta-refresh در مرورگرها یکسان نیست؛ این محیط تضمین مطلق قطع همه مسیرهای شبکه نیست. کد ناشناس را همچنان با احتیاط وارد کنید.
4. پیام موفقیت محلی به معنی تأیید همگام‌سازی ابری نیست. وضعیت دقیق pending/failed ابر و بازطراحی lifecycle زیرساخت مشترک cloudStateSync در این تغییر انجام نشده‌اند.

## چهار پیشنهاد اولویت‌دار برای مرحله بعد

1. **ویرایشگر کد سبک:** شماره خطوط، جست‌وجو، تورفتگی و کمک برای یافتن محل خطا؛ کاربردی‌ترین گام بعدی برای ویرایش HTML.
2. **قالب‌های آماده آفلاین:** محاسبه‌گر، چک‌لیست و تایمر با ظاهر و رنگ هماهنگ برنامه، بدون CDN یا درخواست اینترنتی.
3. **تاریخچه نسخه و مقایسه کد:** ذخیره چند نسخه محدود و امکان بازگشت قبل از تغییرات بزرگ، بدون جایگزین‌کردن پیش‌نویس‌های قابل‌بازیابی موجود.
4. **پیش‌نمایش موبایل/تبلت/دسکتاپ:** تغییر عرض قاب برای بررسی واکنش‌گرایی بدون تغییر کد یا اجرای خودکار هنگام تایپ.
