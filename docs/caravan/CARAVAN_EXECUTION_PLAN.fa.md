# دستور ادامه برای لونا با بالاترین تفکر

ابتدا EXECUTION_STATUS.fa.md و Git را بخوان؛ یافته‌های محیط قبلی را شاهد وجود کد یا دارایی در این محیط فرض نکن. مخزن Arshiam، شاخه مقصد PR arshnaz و شاخه اجرا fix/caravan-reliability-and-eight-directions است. تغییرات قبلی را حفظ کن؛ reset، clean، force push، merge و انتشار production انجام نده.

مراحل ۱ تا ۴ اکنون اصلاح و با آزمون‌های ثبت‌شده بررسی شده‌اند؛ از صفر بازنویسی نکن. برای نقاط حساس ذخیره، journal و cloud، سناریوی کوچک قابل‌بازتولید بساز؛ پس از دو تلاش متفاوتِ ناموفق، شواهد را برای بازبینی مدل قوی‌تر ثبت کن و کارهای مستقل را ادامه بده.

اول مرحلهٔ ۵ را با دارایی‌های تأییدشده تکمیل کن. نبودن دارایی‌ها را جعل نکن و تصویر تازه جای مراجع تأییدشده نگذار. جهت‌های cardinal و diagonal و ترتیب متفاوت ردیف گوراستاخ/فرشته را از manifest بخوان. حرکت هشت‌جهته با crossfade 160ms و hysteresis؛ جهت آخر هنگام توقف حفظ شود. انتخاب ظاهر هر دو شخصیت مستقل، سه رنگ مو و سه لباس، ماندگار پس از Reload و cloud restore. آلبوم lazy-load با ۲۴ کارت؛ تصویر بزرگسالی فقط یکی دو نقطهٔ مناسب روایت. Default فرشته مشکی و گوراستاخ سفید، لباس‌های اولیه.

سپس مرحلهٔ ۶: همهٔ ابزارها قابل‌دسترسی، منوی واحد، بدون هم‌پوشانی در موبایل/تبلت/دسکتاپ، inputهای dialog حرکت را فعال نکنند؛ گروه‌های مناطق غیرفعال هم پنهان و هم از tick حذف شوند؛ یک animation loop، delta-time، reduced-motion و سقف DPR. تغییر موتور یا جهان تازه خارج از دامنه است.

مرحلهٔ ۷: آزمون‌های موجود مرتبط را اجرا کن، تست جدید فقط برای رفتار تازه؛ typecheck، build، lint تغییرها و diff --check. خروجی build را در مرورگر هم باز کن. برای هر مرحله commit و وضعیت واقعی؛ نتیجهٔ mock با Firebase زنده یکی نیست. Feature branch را push و PR به arshnaz بساز اگر دسترسی معتبر است؛ در صورت denial، بستهٔ تک‌فایلی از تغییرها و شرح محدودیت تحویل بده. main و شاخه‌های دیگر دست‌نخورده بمانند.

بازبین Sol: diff نسبت به مبنا و آزمون‌ها را بررسی کن، به‌خصوص خراب‌شدن ذخیره، replay با درخواست یکسان، قطع و timeout، تعویض حساب و پاسخ دیررس، server revision و نگه‌داشتن نسخه محلی در conflict. مشکل قابل‌اثبات را با سناریو و شدت گزارش و اصلاح کن؛ feature تازه اضافه نکن.
