# تکمیل معیار موبایل Plan

مبنای کار: `main` در commit `e70aff4`. این اصلاح، مورد ۱۰ گزارش ۱۷‌گانه و معیار نبود overflow افقی در بستهٔ ۰۶ را تکمیل می‌کند.

## نقص و اصلاح

در نمای هفته، تسکِ دارای برچسب هدف طولانی می‌توانست حداقل عرض ستون اصلی grid را بزرگ‌تر از viewport کند. در fixture بازتولید، `document.documentElement.scrollWidth` برای viewport ۳۶۰ پیکسل در فارسی ۳۸۳ و در انگلیسی ۴۱۴ پیکسل بود؛ انگلیسی در ۳۹۰ پیکسل نیز تا ۴۱۴ پیکسل می‌رفت. این همان الگوی overflow ثبت‌شده در تصاویر بستهٔ ۰۶ است؛ اندازهٔ دقیق به داده و فونت fixture وابسته است.

فقط کلاس `min-w-0` به ستون اصلی `PlanningBoard` اضافه شد تا grid بتواند آن را در عرض موجود جمع کند. متن برچسبِ طولانی در اندازهٔ کارت موجود کوتاه‌نمایی می‌شود؛ markup، رنگ، فونت، ساختار کارت و چیدمان عمومی تغییر نکرد.

## تأیید

- fixture با دادهٔ ساختگیِ دارای هدف طولانی، زیرکار و کار انجام‌شده در Chromium اجرا شد. در هر ۱۲ ترکیبِ عرض‌های ۳۶۰/۳۹۰/۱۲۸۰، فارسی/انگلیسی و روشن/تاریک، عرض document با viewport برابر بود؛ انتخابگر دوره هم در حالت باز و بسته بررسی شد.
- نمونهٔ پس از اصلاح در `/workspace/plan-research/plan-overflow-after-{360,390,1280}-{fa,en}-{light,dark}.png` است. تصاویر baseline بستهٔ ۰۶ در همان پوشه با نام `packet06-current-*` نگهداری شده‌اند.
- آزمون‌های مرتبط `PlanningBoard.test.tsx` و `PlanItemCard.test.tsx`: ۲ فایل، ۸ تست موفق. `npm run typecheck` و `npm run build`: موفق. build تنها هشدارهای قبلی دربارهٔ اندازهٔ chunk را داشت.
- fixture موقت پس از بررسی حذف شد و وارد Git نشد. Chromium در dev harness خطای اتصال WebSocket محلی گزارش کرد؛ Plan render شد و اندازه‌گیری و تصویر در همهٔ حالت‌ها ثبت شدند.

این تغییر فقط overflow ثبت‌شدهٔ Plan را هدف می‌گیرد. آزمون‌های کامل فرانت‌اند و API در بازبینی پیش از ادغام `08_PRE_MAIN_SOL_REVIEW_FA.md` موفق بودند؛ چون این commit فقط یک کلاس چیدمان را تغییر می‌دهد، مجموعهٔ کامل دوباره اجرا نشد.
